# Сайт-портфолио Алисы

Одностраничный сайт-портфолио с админкой. В админке меняются все тексты и загружаются фото.

**Стек:** Node.js 22 (Express) · PostgreSQL 17 · nginx 1.28 · Docker Compose. Фреймворков на фронтенде нет: чистые HTML, CSS и JavaScript.

```
portfolio-site/
├── backend/          API, серверный рендер страницы, вход в админку, загрузка фото
├── frontend/static/  стили и скрипты сайта
├── frontend/admin/   админка
├── nginx/            веб-сервер: HTTPS, заголовки безопасности, лимиты, защита от сканеров
├── deploy/           fail2ban и systemd для боевого сервера
└── docker-compose.yml
```

## Быстрый запуск на своём компьютере

Нужен Docker Desktop.

```bash
cp .env.example .env
```

В `.env` поставьте значения для локальной проверки:

```
DOMAIN=localhost
PUBLIC_ORIGIN=http://localhost:8080
ADMIN_PATH=my-secret-admin-2026
POSTGRES_PASSWORD=любой-длинный-пароль
COOKIE_SECURE=false
# если порт 8080 занят другим проектом — поставьте свободный (например 8792) здесь и в PUBLIC_ORIGIN
HTTP_PORT=8080
HTTPS_PORT=8443
```

```bash
docker compose up -d --build
docker compose exec api node src/cli/admin.js create Alica
```

Вторая команда выведет логин и пароль. После этого:

- сайт: http://localhost:8080
- админка: http://localhost:8080/my-secret-admin-2026/

## Развёртывание на сервере (VPS)

Подойдёт любой VPS с Ubuntu 22.04/24.04, 1 ГБ RAM и доменом, у которого A-запись указывает на IP сервера.

**1. Подготовьте сервер**

```bash
# Docker
curl -fsSL https://get.docker.com | sh
# Файрвол: только SSH, HTTP и HTTPS
ufw allow OpenSSH && ufw allow 80/tcp && ufw allow 443/tcp && ufw enable
# Автоматические обновления безопасности
apt install -y unattended-upgrades fail2ban
```

Вход по SSH сделайте только по ключу: в `/etc/ssh/sshd_config` укажите `PasswordAuthentication no` и `PermitRootLogin prohibit-password`.

**2. Загрузите проект и заполните `.env`**

```bash
cd /opt && git clone <репозиторий> portfolio-site && cd portfolio-site
./scripts/gen-env.sh ваш-домен.ru
```

Скрипт создаёт `.env` со случайным адресом админки и паролем базы и выводит адрес админки — сохраните его в менеджере паролей. Заполнить вручную тоже можно: `cp .env.example .env && nano .env`, секреты генерируются командами `openssl rand -hex 12` (ADMIN_PATH) и `openssl rand -base64 32 | tr -d '/+='` (POSTGRES_PASSWORD).

На сервере обязательно `COOKIE_SECURE=true`, а `PUBLIC_ORIGIN=https://ваш-домен`.

**3. Запустите сайт и получите HTTPS-сертификат**

```bash
mkdir -p certbot/conf certbot/www
docker compose up -d --build
docker compose run --rm --entrypoint certbot certbot certonly --webroot -w /var/www/certbot \
  -d ваш-домен.ru --email ваша@почта.ru --agree-tos --no-eff-email
docker compose --profile tls up -d certbot
sleep 15 && docker compose restart nginx
```

Контейнер certbot открывает сертификат для nginx и потом продлевает его автоматически. После перезапуска nginx сам переходит на HTTPS: так происходит, когда для домена есть сертификат. Проверить: `docker compose logs nginx | grep режим` должно показать «режим HTTPS».

**4. Создайте администратора**

```bash
docker compose exec api node src/cli/admin.js create Alica
```

Войдите в админку и сразу включите двухфакторную защиту в разделе «Безопасность».

Другие команды: `reset Alica` — новый пароль, `rename Alica НовыйЛогин` — сменить логин (все сессии завершаются), `list` — список администраторов.

**5. Проверьте защиту снаружи**

С любого компьютера (Linux, macOS или Git Bash на Windows):

```bash
./scripts/security-check.sh https://ваш-домен.ru
```

Скрипт проверяет заголовки, отсев сканеров, обход путей, закрытые методы, API без входа, CSRF, SQL-инъекции и лимиты. С переменными `ADMIN_USER`/`ADMIN_PASS` он дополнительно проверяет сессии и загрузку опасных файлов, а с `BRUTEFORCE=1` — защиту от перебора (это займёт пару минут и временно заблокирует ваш IP для тестового логина).

## Стартовое содержимое

При самом первом запуске сайт заполняется текстами из резюме. Фото Алисы из `backend/seed/photos/` и фото проектов из `backend/seed/projects/` автоматически загружаются в медиатеку и расставляются по разделам. Дальше всё меняется только через админку: повторные запуски ничего не перезаписывают.

Что стоит проверить и поправить в админке перед публикацией:

- **«Проекты (мероприятия)».** Шесть кейсов из папки «Проекты Фриланс» с двумя фото каждый. Описания мероприятий и задачи написаны по фото, а цифры в «Результатах в цифрах» — типовые для SMM-сопровождения таких событий. Замените их на реальные. Новые проекты добавляются кнопкой «+ Добавить проект», фото — через «Выбрать фото».
- **Ролики.** Раздел «Работы: ролики и примеры контента» пока пустой и на сайте не показывается — добавьте туда Reels и клипы Алисы. Ролики с мероприятий добавляются прямо в проект: «Проекты (мероприятия)» → проект → «Ролики с мероприятия». Показывайте только то, что Алиса снимала или монтировала сама.
- **CarX 2026.** По данным прессы, форум автобизнеса CarX 2026 прошёл 6 октября в отеле «МонАрх» (организатор — «Автостат»), а в описании на сайте указаны концертный зал, экспозиция машин и стенды DRIVE2 и PUNKT E. Проверьте у Алисы, о каком мероприятии фото, и поправьте описание.
- **«Графики роста».** Сейчас там примерные значения, которые сходятся с цифрами из резюме. Замените их на настоящие данные из статистики аккаунтов: на собеседовании могут попросить показать источник.
- **«Увлечения».** Тексты написаны условно — поправьте под реальные интересы Алисы.
- **«Оформление» → «Фоновые фото».** Сейчас там два снимка Алисы. Загрузите фото с мероприятий и съёмок: на сайте они показываются чёрно-белыми и полупрозрачными на фоне «Результатов», «Навыков» и «Контактов». Там же меняется текст круглого значка у главного фото.
- **«Контакты»:** Telegram, почта, телефон. Пока они пустые, кнопки «Написать» и «Связаться» не показываются.
- **«Главный экран»:** фамилия и город.

## Как пользоваться админкой

- **Тексты:** выберите раздел слева, измените поля и нажмите «Сохранить» (или Ctrl+S). Изменения сразу появятся на сайте.
- **Фото:** загрузите их в «Медиатеке» или прямо из поля «Фото». Затем выберите фото в «Главном экране» или «Работах» и сохраните.
- **Видео:** два способа.
  - *Ссылка.* Если ролик уже лежит в VK Видео, YouTube или Rutube, вставьте ссылку в поле «…или ссылка на ролик» (подходят обычная ссылка, ссылка «Поделиться» и код `<iframe>`). На сайте плеер площадки загружается только после нажатия на ролик, до этого показывается обложка: фото из поля «Фото или обложка ролика» или, в проекте, фото мероприятия.
  - *Файл.* MP4, MOV или WebM до 200 МБ и 10 минут загружается в «Медиатеке» или из поля «Видеофайл». Сервер удаляет из файла метаданные (геопозицию, модель телефона) и делает кадр-обложку. Ролики с iPhone (HEVC) и файлы больше 1920 px он перекодирует в H.264, чтобы они играли во всех браузерах. Обработка занимает от нескольких секунд до пары минут.
  - *Формат.* Вертикальный (9:16) или горизонтальный (16:9) определяется автоматически, а в поле «Формат ролика» его можно задать вручную.
  - Ограничения меняются переменными `MAX_VIDEO_MB` и `MAX_VIDEO_SECONDS` в `docker-compose.yml`. При изменении размера поменяйте и `client_max_body_size` у `/api/admin/media/video` в `nginx/templates/locations.inc.template`.
- **Пустые блоки не показываются.** Например, раздел «Работы» появится на сайте, когда в нём будет хотя бы одна карточка с фото.
- **Стиль сайта:** в разделе «Стиль сайта» выбираются фон блока «Проекты» (эспрессо, песок, пудра, шалфей, карамель), фон страницы, акцентный цвет и шрифт заголовков. Там же включаются и выключаются анимации, зерно, линии-сетка и подписи на полях. Доступен только выбор из готовых вариантов: свой CSS или произвольный цвет ввести нельзя, поэтому вёрстку не сломать, а все сочетания читаются по нормам контраста.
- **Забыли пароль:** `docker compose exec api node src/cli/admin.js reset Alica`. Это сбросит пароль и 2FA и выполнит выход на всех устройствах.

## Что сделано для безопасности

**Вход в админку**

- Админка открывается по секретному адресу `ADMIN_PATH`, а `/admin` возвращает 404.
- Пароли хранятся как хеш scrypt с солью.
- После 5 ошибок вход блокируется: сначала на 15 минут, потом дольше, максимум на сутки.
- Действуют лимиты на вход: в nginx 5 попыток в минуту с IP, в приложении 10 попыток за 15 минут на IP и на логин.
- Время ответа не выдаёт, существует ли логин.
- Можно включить двухфакторную защиту (TOTP: Яндекс Ключ, Google Authenticator). Один и тот же код нельзя использовать повторно.
- Сессия хранится в cookie `__Host-` с флагами HttpOnly, Secure и SameSite=Strict. В базе лежит только хеш токена.
- Сессия завершается через 2 часа бездействия, максимум через 12 часов. После смены пароля выполняется выход на всех других устройствах.
- Изменяющие запросы защищены от CSRF: нужен токен в заголовке и запрос с того же домена.
- Можно разрешить вход только с определённых IP: `ADMIN_IP_ALLOWLIST`.
- Все действия пишутся в журнал: входы, неудачные попытки, сохранения, загрузки. Журнал виден в админке.

**Данные и XSS**

- Каждое сохранение проверяется по схеме. Лишние поля отбрасываются, длина ограничена, управляющие символы удаляются.
- На странице весь текст экранируется. Ссылки на Telegram, почту и телефон собираются только из проверенных значений, поэтому `javascript:` в них не попадёт.
- В админке интерфейс строится через `textContent`, без `innerHTML`.
- Строгая Content-Security-Policy запрещает встроенные и сторонние скрипты, стили и iframe.
- Все SQL-запросы параметризованы.

**Загрузка фото**

- Принимаются только изображения до 15 МБ. Тип определяется по содержимому файла, а не по расширению.
- Каждое фото перекодируется в WebP. При этом удаляются EXIF-данные (геопозиция, модель телефона) и всё, что могло быть спрятано в файле.
- Слишком большие по разрешению картинки отклоняются: это защита от «бомб».
- Имена файлов — случайные UUID. nginx отдаёт из `/media/` только файлы вида `<uuid>.webp`.

**nginx**

- Заголовки: HSTS, CSP, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy, COOP и CORP.
- Только TLS 1.2 и 1.3 по профилю Mozilla Intermediate.
- Лимиты частоты запросов и числа соединений с одного IP. Короткие таймауты защищают от slowloris.
- Запросы на IP сервера и чужие домены обрываются без ответа: на этом отсеивается большая часть ботов.
- Пути сканеров обрываются кодом 444: `.env`, `.git`, `wp-admin`, `phpmyadmin`, `*.php` и т. п.
- Известные сканеры по User-Agent блокируются: sqlmap, nikto, nuclei, masscan и др.
- Версия nginx скрыта. Работают только методы GET, HEAD, POST, PUT, PATCH и DELETE.

**Docker**

- Контейнеры работают не от root, с `no-new-privileges` и ограничением памяти и процессов. Права на том с фото выставляет одноразовый контейнер `uploads-init`.
- У API и nginx отключены все Linux capabilities.
- Файловая система API доступна только для чтения.
- База доступна только во внутренней сети без выхода в интернет. Наружу открыт только nginx.
- Зависимости зафиксированы в `package-lock.json`, `npm audit` — 0 уязвимостей.

## fail2ban: бан сканеров на уровне сервера

nginx уже обрывает подозрительные запросы. fail2ban дополнительно банит такие IP на сутки целиком.

```bash
cp deploy/fail2ban/filter.d/nginx-portfolio.conf /etc/fail2ban/filter.d/
cp deploy/fail2ban/jail.d/nginx-portfolio.local /etc/fail2ban/jail.d/
cp deploy/systemd/portfolio-nginx-log.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now portfolio-nginx-log
systemctl restart fail2ban
fail2ban-client status nginx-portfolio
```

Если проект лежит не в `/opt/portfolio-site`, поправьте путь в `portfolio-nginx-log.service`.

## Резервные копии

```bash
# База
docker compose exec -T db pg_dump -U portfolio portfolio | gzip > backup-$(date +%F).sql.gz
# Фото
docker run --rm -v alisa-portfolio_uploads:/data -v "$PWD":/backup alpine tar czf /backup/uploads-$(date +%F).tgz -C /data .
```

Храните копии не на том же сервере. Удобно настроить cron раз в сутки.

## Обновление

```bash
git pull
docker compose up -d --build
docker image prune -f
```

Раз в месяц выполняйте `cd backend && npm audit` и обновляйте образы командой `docker compose pull && docker compose up -d --build`.

## Если сайт будет за Cloudflare

nginx будет видеть IP Cloudflare вместо IP посетителей, и лимиты сработают неправильно. Добавьте в `nginx/nginx.conf` блок `set_real_ip_from` с диапазонами Cloudflare и `real_ip_header CF-Connecting-IP;`.

## Тесты

```bash
cd backend && npm ci && npm test
```

Тесты проверяют хеширование паролей, TOTP (по тестовому вектору RFC 6238), защиту от повторного кода, проверку данных и экранирование HTML (в том числе подстановкой XSS-строк во все поля схемы).

На GitHub при каждом push запускаются тесты, `npm audit` и сборка Docker-образов (`.github/workflows/ci.yml`). Dependabot раз в неделю предлагает обновления зависимостей и базовых образов.
